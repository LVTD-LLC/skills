# Repository Instructions

## Source Of Truth

- Author skills in `skills/<skill-name>/`.
- Every skill must have `skills/<skill-name>/SKILL.md`.
- Do not hand-edit `.claude-plugin/`, `.agents/plugins/`, or `plugins/`. They are generated marketplace artifacts.
- Project-installed workflow skills live in `.agents/skills/<skill-name>/` and are managed by the `skills` CLI. Do not hand-edit installed skill copies; reinstall or update them with the CLI and commit the resulting copied skill changes. Do not commit `skills-lock.json` for local-only installs because it records machine-local source paths.
- `dist/registry.json` is generated by `npm run build` and is intentionally ignored.

## Adding Or Updating A Skill

1. Use a lowercase hyphen-case directory name, for example `skills/django-htmx/`.
2. Keep `SKILL.md` frontmatter complete:

   ```yaml
   ---
   name: django-htmx
   description: Build and review HTMX interactions in Django server-rendered projects.
   license: MIT
   compatibility: Codex, Claude Code, and other Agent Skills-compatible clients.
   metadata:
     version: "0.1.0"
     displayName: Django HTMX
     category: Web Development
     tags: django,htmx,server-rendered-ui
   ---
   ```

3. Put large examples, fixtures, or scripts under the same skill directory.
4. When a skill uses external source material, attribute the source in the skill
   package. Include links where stable public URLs exist, and use title/author
   plus chapter, section, or topic references for books and long-form sources
   when useful.
5. If a skill includes `scripts/`, make executable script files executable.
6. Run `npm run check` before finishing.
7. Commit source skill changes together with regenerated marketplace artifacts.

## Validation Commands

```bash
npm run validate
npm run build
npm run validate:marketplaces
npm run check
```

Use `npm run check` as the default final command. It validates skills, rebuilds registry and marketplace artifacts, validates generated marketplace files against source skills, and fails if committed generated artifacts are stale.

## Project-Installed Helper Skills

Use the project-installed skills in `.agents/skills/` for book-to-skill and skill-authoring work in this repository:

- `skill-creator`: use when creating or updating a skill, especially for naming, frontmatter, progressive disclosure, resource layout, and validation expectations.
- `write-a-skill`: use when drafting or refining concise `SKILL.md` instructions, trigger descriptions, examples, and split-reference structure.
- `ebook-analysis`: use when parsing ebooks, extracting concepts or entities with citation traceability, or synthesizing knowledge across books before deciding what skills to create.
- `skill-from-book`: use when converting book markdown into reusable skill packages with phased analysis, extraction planning, references, workflows, and progress tracking.
- `pdf`: use when source material or deliverables are PDFs and layout/rendering matters; render pages and inspect visual output instead of relying only on text extraction.

For book-to-skill projects, prefer this order: use `pdf` only when the source is PDF, use `ebook-analysis` for traceable reading/extraction, use `skill-from-book` to structure reusable skill packages, then use `skill-creator` and `write-a-skill` to finalize concise, valid skills.
